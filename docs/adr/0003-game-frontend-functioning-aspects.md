# ADR 0003: Особенности построения и функционирования фронтенда

- **Статус:** созданы страницы авторизации и регистрации, необходимо разработать game.html - главную страницу игры
- **Дата:** 2026-10-25
- **Область:** стрраница game.html и   `ручки`, обрабатывающие асинхронные запросы, генерируемые js на странице game.html 

## Контекст и состояния фронтенда

Для игрока (назовем его игрок А) существуют пять состояний, в которых может находится его страница игры, соответстующим состояниям игрока А на фронтенде: не присоединился, выбирает маршрут, играет, выиграл, раунд закончился для него без победы. 
1) А еще не участвовал в этом раунде, не присоединился к раунду - он видит состояние `Статистика игры` и, либо кнопку `Присоединиться к игре`, либо сообщение `Новая игра вот-вот начнется` если игроку не повезло, и он вошел в то время, когда истекают последние секунды текущего раунда.  
2) Игрок А только что кликнул на кнопке `Присоединиться к игре` - интерфейс его страницы игры переключается в состояние `выбор маршрута`. Бэкенд для него сгенерировал пару городов и игроку предлагается, кликая на отрезках линий (путями) между промежуточными городами, сформировать непрерывный путь (граф) ведущий от одного из предложенных ему городов до другого. JS-скриптом фронтенда зафиксирован непрерывный путь: Появляется диалог `Подтверждаете выбор пути? Да/Нет` и, при подтверждении, на бэкенд отправляется асинхронный запрос с данными о пути, ожидающий в ответе данные кроссворда, сформированного для этого пути. Бэкенд перед формированием и выдачей фроненду кроссворда должен проверять связность, соответствие назначенным городам, отсутствие циклов и повторных участков; клиентская проверка нужна только для удобства.
3) Игроком Выбор сделан, переход к состоянию `играет` - ломаная линия, состоящая из выбранных игроком отрезков (выбранный путь) выделена ярким цветом, фронтенд сделал запрос с данными о выбранных роутах и получает от бэкенда данные о сгенерированных для этих отрезков словах кроссворда (и Описаний к ним).  Фронтенд (страница) данного игрока А в состоянии `основной игровой процесс`. В начале этого состояния на линиях `выбранного пути` строится последовательность прямоугольничков кроссворда (с некоторвм замедлением, игрок А видит процесс появления кроссворда в динамике). Клинув мышкой на любом прямоугольничке кроссворда, игрок `открывает` диалог с описанием `спрятанного` в прямоугольничке слова для угадывания вверху, полем для ввода ответа (`догадкой` игрока для загаданного слова) и кнопками `Ответить` и `Попросить подсказку` в нижней части диалогового окна. 
Уточнение, о котором говорилось и ранее: если часть выбранного игроком пути совпадает с выбранным другим игроком путем, то: а) другой игрок уже угадал это слово - вместо прямоуголников кроссорда появляется разгаданное слово, б) если другой игрок ранее выбрал тот же участок пути, но еще не угадал слова на этом (совпадающем) участке - игрок А получает  на этом участке слова кроссворда, загаданные для этого другого игрока.
4) Игрок А угадал все слова кроссворда на своем пути между городами - выиграл - его интрефейс переходит в состояние `Поздравления с выигрышем`, с прорисовкой всех участков его пути в виде двойной линии (железной дороги), надписью `Поздравляем! Вы успешно завершили игру и заработали XXX очков!`, возможно, салютом из конфетти библиотеки confetty.js и демонстраницией гифки с `проносящимся по рельсам поездом`- и переход в состояние / блок `Статистика игры`.
5) Возможно, игрок А столкнется с ситуацией, когда раунд для него закончился без победы: другой игрок сумел выиграть в этом раунде (или игра завершилать по `expired`) - тогда игрок получает сообщение `К сожалению, другой игрок добился успеха, Вам повезет в следующий раз!` (или если по `expired`, то сообщение `К сожалению, время игры истекло`) и интерфейс игры переходит в состояние `Статистика игры`.

## Особенности реализации

В любом состоянии на странице game.html вверху присутствует информационная панель с названием игры и таймером, отсчитывающим время до завершения игры по `expired`. Оставшееся до завершения игры Время приходит из Бэкенда, если текущий раунд существует.
Когда на таймере остается времени меньше минуты - таймер меняет цвет на красный и мигает.   

Карта, на фоне которой `отрисовываются` кружочки городов, пути между городами (на основе данных из `routes`) представляет собой находящийся в /frontend/static/img рисунок map.svg размерами 4000 x 3000 пикселей. Он не должен никак масштабироваться. Просто демонстрируется в блоке в режиме overflow: scroll. Игрок будет перемещать его (рисунок/карту) мышкой внтури мньшего по размеру блока в котором находится этот рисунок/карта на Десктопе. На телефоне карта должна перемещаться влево-вправо, вверх-вниз скользящим движеним пальца по экрану телефона. При этом, все кружочки городов (и их названия), а так же, соединяющие города линии (пути) должны перемещаться вместе с рисунком (как бы, быть `прилеплены` к нему). Предлагается карту загружать в самом начале при открытии страницы game.html. Координаты каждого города в cities соответствуют координатам на карте (соответствуют рисунку map.svg 4000 x 3000).  

В состоянии выбора маршрута (2) у соединяющих города `возможных путей` (отрезков линий) должны быть обработчики событий oveflow и click, чтобы при наведении курсора, линия меняла цвет, а при клике - этот цвет `фиксировался` и данный путь заносился бы в массив выбранных игроком путей (а при повторном клике, менял снова цвет на обычный серый и удалялся из массива) - это для Десктопа. На телефоне выбор маршрута осуществляется "тапом" по нужному участку пути. Как только образовалась неперерывная ломаная от (условно) начального города к конечному - на странице появляется диалоговое окно подтверждения `Зафиксировать выбранный маршрут? (Да/Нет)` и если выбор подтвержден, то данные передаются на бэкенд, с бэкенда возвращаются данные для отрисовки кроссворда данного ирока, а интрефейс переходит в состояние (3).

Состояние `статистика игры` означает, что поверх карты демонстрируется dialog с одним из сообщений о состоянии игры (`Новый раунд игры вот-вот начнется`, `Текущий раунд игры стартовал XX минут назад. К игре присоединилось игроков: YY`) и, ниже этой надписи, таблчка со списком всех победивших ранее хотя бы в одном раунде игроков и набранными ими суммарными по итогам всех раундов очками (в порядке убывания очков) из таблицы GameResult. Под таблицей раполагаются в ряд три картинки winner.svg (лавровый венок) из /frontend/static/img/ c `вписанными` (размещенными поверх картинок) именами трех игроков с наибольшими суммарными очками (если таковых не набирается - просто картинка winner.svg - без имени пользователя поверх). Внизу диалогового окна располагается кнопка `Присоединиться к игре` если есть активный раунд и до его завершения не меньше минуты. 

Квадратики кроссворда (изначально - пустые белые блоки с темно-серым бордером), соответствующие отдельным загаданным словам, `рисуются` должны быть расположены вдоль линий, соединяющих города (маршрутов) симметрично линиям, поверх этих линий. Как только игрок угадал какое-нибудь слово кроссворда, буквы этого слова появляются в соответствующих этому слову квадратиках кроссворда. Если данное слово еще не угадано, то клик по квадратикам (тап - на телефоне) вызывает диалоговое окно с описанием слова, полем ввода для слова, предложенного игроком и кнопками `Ответить` и `Попросить подсказку` 

Общее количество загаданных слов кроссворда (пустых квадратиков кроссворда, изначально) на участке между двумя смежными городами маршрута должно быть не больше значения `length_in_letters` - 2 (где `length_in_letters` - поле из таблицы ДБ `routes`). Слова для данного участка выбираются последовательно по правилу `длина_очередного_слова` <= `length_in_letters` - `дина_выбранных_ранее_слов` - 2  и если длина последнего слова получается меньше 3 по этому правилу (`длина_последнего_слова`=`length_in_letters`-`дина_всех_уже_выбранных_слов`- 2), то процесс добавления (выбора) слов для этого участка пути останавливается, оставляем пустое место, которое будет распределено как промежутки между уже выбраннми словами участка.
