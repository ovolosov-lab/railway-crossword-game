 # ADR 0006: Убрать из приложения тип подсказки `category` и всё что с ним связано
 
 **Статус:** решение принято; изменения ожидают реализации
 - **Дата:** 2026-10-31
- **Область:** модель, PostgreSQL и функционирование раунда игры (фронтенд и бэкенд)

## Контекст

Подсказка `Категории` не облегчает никоим образом отгадывание кроссворда игроком и, следовательно - бессмысленна. И, поэтому, принято решение - исключить данную подсказку из жизненного цикла игры.
В связи с с удаленем этого типа подсказки, исчезает смысл в наполнении данными и самом существовании объектов ORM и PostgreSQL, созданных ранее для работы с данными `Категории`. 

## Решение 

В models.py удалить класс Category, изменить классы DictionaryWord (убрать поля category_id и category, связанные с этим полем индексы и вторичные ключи).

В schemas.py убрать класс CategoryRead, изменить класс DictionaryWordCreate (убрать поле category_id), изменить DictionaryWordClue (убрать поле category_id).

В PostgreSQL DataBase убрать таблицу `Categories`, а структура таблицы `dictionary_words` стать быть такой, как показано ниже: 

### `dictionary_words` (НОВЫЙ ВАРИАНТ - ЕГО СЧИТАТЬ ЕДИНСТВЕННО ПРАВИЛЬНЫМ)

| Поле | SQLAlchemy / PostgreSQL | Правила |
|---|---|---|
| `id` | `Integer`, PK | identity |
| `word_text` | `String(100)` | NOT NULL, отображаемая форма: существительные в нормализованной форме  |
| `definition` | `Text` | NOT NULL; описание, показываемое игроку |
| `language_code` | `String(5)` | NOT NULL, BCP 47 language tag |
| `letter_count` | `SmallInteger` | NOT NULL, CHECK `> 0`; число букв после нормализации |
| `is_active` | `Boolean` | NOT NULL, default true |
| `created_at` | `DateTime(timezone=True)` | NOT NULL, UTC | 

В скриптах загрузки учесть эти изменения структуры данных: данные о категориях теперь будут отсутствовать, их не нужно загружать. Данные для загрузки в таблицу `dictionary_words` будут содержать только колонки `слово` и `объяснение слова`. В поле `language_code` для MVP проекта достаточно загружать только константу `ru`. В поле `letter_count` загружается вычисленная в момент загрузки длина загружаемой в поле `word_text` строки — колонки `слово`.
Миграции настроить в соответствии с внесенными изменениями.

### Подсказки - изменения
Каждому игроку доступны две подсказки в текущем раунде игры: 1) первая буква слова 2) последняя буква слова. Воспользовавшись подсказкой, игрок каждый раз теряет заданное в настроечных параметрах количество очков (например: первая подсказка - 10 очков, вторая - 20 очков). Поэтому, подсказки запрашиваются запросом к бэкенду и запрошенные в текущем раунде подсказки нужно для данного пользователя хранить в течение раунда в инстансе для данного пользователя (в объекте, хранящем данные текущего раунда в памяти), чтобы очки не списывались у игрока повторно за уже ранее запрошенную подсказку, которую игрок запросил повторно. 

Теперь в запросе фронтенда бакенду допустимы только типы подсказок: `hint_type`: `first_letter` или `last_letter`. Значение `hint_type=unknown` по-прежнему, допустима в ответе, может возвращаться только в ответе запроса для недоступной подсказки и не является допустимым типом запрашиваемой подсказки.

Необходимо удалить остатки из состояния игры, настроек и тестов. В текущей реализации ещё есть `category` в `HintType` и `HintUsed`, настройка стоимости в `config.py` и её применение в `ActiveGame.use_hint` - здесь тоже не должно быть категории. 

### Миграции
Сейчас в существующей миграции создаются таблица `categories`, `FK category_id` и индекс по `(language_code, category_id, letter_count)` — `0272a23d24a3_create_game_domain_tables.py`. Не изменять уже применённую миграцию: добавить новую Alembic-миграцию, которая удаляет FK и старый индекс, удаляет `category_id` и таблицу `categories`, а затем создаёт индекс активного поиска по `(language_code, letter_count) WHERE is_active`. При downgrade восстановить прежнюю схему, но не выдумывать удалённые категории и связи слов; ограничение восстановления данных должно быть явно указано в миграции.
