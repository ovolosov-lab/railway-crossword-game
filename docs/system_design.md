# System Design: Веб-игра "Построй железную дорогу" (Кроссворд)

## 1. Общее описание
Многопользовательская игра, где игроки угадывают слова (кроссворды), расположенные на путях между городами Европы на интерактивной карте. Угаданное слово "строит" участок рельсов. Цель каждого игрока - проложить путь (железную дорогу) между двумя городами, назначенными каждому вошедшему в игру игроку случайным образом.

## 2. Стек технологий
- **Backend:** Python 3.11+, FastAPI (асинхронный), Uvicorn
- **Database & ORM:** PostgreSQL, SQLAlchemy 2.0 (async), Alembic для миграций
- **Frontend:** Vanilla HTML5, CSS3 (Tailwind по желанию), JavaScript (Async/Fetch, Leaflet.js или SVG для карты)
- **AI Integration:** OpenAI API протокол (генерация описаний слов через LLM)
- **Auth:** JWT-токены (хранение в HttpOnly Cookies)
- **DevOps:** Docker, Docker Compose (сервисы: app, db)
- **Logging:** Loguru

## 3. Сущности и База данных

Долговечные данные: **User**, **City**, **Route** (участок сети), **DictionaryWord** и **GameResult**. Названия городов уникальны в каталоге и городов на карте - не больше 60; большинство записей — столицы, но это не обязательное ограничение. Участок может требовать несколько слов: `length_in_letters` в хранит максимальное количество помещающихся на участке букв, а не географическое расстояние. Слова назначаются маршрутам случайно из словаря; словарь не закреплён за участком.

Активный раунд, его сетка и прогресс отгадывания — временное состояние приложения, не таблицы `Game` и `Word`. Cлова кроссворда расположены строго вдоль линии, соединяющей города и НЕ могут пересекаться, между словами - небольшой интервал, разделяющий их; расположение задаётся в состоянии раунда, а не в словаре или маршруте. Пока используется память одного процесса; до горизонтального масштабирования активное состояние планируется перенести в Redis. После завершения в PostgreSQL сохраняется итог раунда. Детали описаны в [ADR 0001](./adr/0001-game-domain-and-storage.md).

## 4. Архитектура Проекта
Проект разделен на изолированные контексты бэкенда и фронтенда:
- `backend/app/` — асинхронный FastAPI код.
- `frontend/` — статика, шаблоны Jinja2 и сборщик Tailwind CSS.
```text
📂 Мой_Проект/
├── 📂 .agent_env/               # Инструкции для ИИ-агентов
├── 📂 docs/                     # Текстовая документация (System Design, Backlog)
├── 📂 logs/                     # Логи от Loguru (в .gitignore)
│
├── 📂 backend/                  # ВЕСЬ БЭКЕНД ЗДЕСЬ
│   ├── 📂 app/                  # Исходный код FastAPI (внутри каталоги auth, models, routes)
│   ├── 📄 main.py               # Точка входа FastAPI
│   └── 📄 requirements.txt      # Зависимости Python
│
└── 📂 frontend/                 # ВСЯ КЛИЕНТСКАЯ ЧАСТЬ ЗДЕСЬ
     ├── 📂 src/                 # Папка для Tailwind (входной CSS, JS модули)
     ├── 📂 static/              # Скомпилированный CSS, картинки, иконки городов
     │   ├── 📂 css/             # Сюда Tailwind будет собирать финальный файл
     │   ├── 📂 js/
     │   └── 📂 images/
     └── 📂 templates/           # HTML-шаблоны для FastAPI Jinja2
```
