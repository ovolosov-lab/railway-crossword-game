# Игра-кроссворд "Построй железную дорогу" (Веб-приложение)
![License: MIT](https://shields.io) ![Python](https://shields.io) ![PostgreSQL](https://shields.io)

## ✨ Общее описание и стек технологий

Многопользовательская игра, в которой игроки разгадывают кроссворд, расположенный на путях между городами на интерактивной карте. Каждое угаданное слово условно «строит» участок рельсов. Цель игрока — проложить железнодорожный маршрут между начальным и конечным городами, которые назначаются случайно в начале каждого раунда.

Проект представляет собой веб-приложение на базе FastAPI, SQLAlchemy и PostgreSQL. Приложение полностью контейнеризировано с помощью Docker.

**Полный стек технологий:**
- **Backend:** Python 3.11+, FastAPI (асинхронный), Uvicorn
- **Database & ORM:** PostgreSQL, SQLAlchemy 2.0 (async), Alembic для миграций
- **Frontend:** Vanilla HTML5, CSS3, JavaScript
- **Auth:** JWT-токены (хранение в HttpOnly Cookies)
- **DevOps:** Docker, Docker Compose (сервисы: app, db)
- **Logging:** Loguru

> ⚠️ **Важное ограничение текущей версии:**
> Это первая версия приложения (MVP). Для ускорения работы короткоживущие объекты хранятся в оперативной памяти, а не в БД. Из-за этого приложение пока невозможно масштабировать: оно рассчитано строго на **один процесс, один Uvicorn worker и одну реплику**. В дальнейшем для управления состоянием планируется интегрировать Redis.

## 🧠 Ключевые моменты игры

- **Игровая механика:** На карте отображаются города. Два из них случайно назначаются игроку в качестве старта и финиша. Игрок сам выбирает связный маршрут между ними. На линиях выбранного пути генерируется кроссворд, который нужно разгадать для победы в раунде.
- **Мультиплеер:** Несколько пользователей могут играть одновременно, соревнуясь в скорости разгадывания.
- **Непрерывный цикл:** Раунд длится несколько часов и завершается либо по таймауту, либо в момент победы первого игрока. Новый раунд стартует мгновенно.
- **Подсказки:** Доступны две подсказки: открыть первую букву (минус 20 очков) и открыть последнюю букву (минус 30 очков).
- **Игровые очки:** Накопленные баллы (10 очков за каждую букву слова за вычетом штрафов за подсказки) получает только победитель раунда.
- **Совпадающие участки:** Если маршруты игроков пересекаются, очки за общий участок получает тот, кто первым угадал слова. При этом разгаданные буквы сразу становятся видны всем остальным игрокам на этом участке.
- **Игровой словарь:** Слова и их описания автоматически загружаются в БД из CSV-файлов в каталоге `/backend/migrations/words/` при применении миграций Alembic. Вы можете легко дополнить словарь или загрузить свой собственный.
- **Аутентификация:** Аутентификация пользователей выполняется с помощью JWT-токенов (HttpOnly cookie).

## 🏗️ Как устроено приложение

- Для запуска приложения на вашем компьютере или сервере должен быть установлен [Docker](https://docker.com).
- Контекст сборки Docker — корень репозитория. [Dockerfile](../Dockerfile) устанавливает зависимости из `backend/requirements.txt`, копирует backend и frontend в образ и запускает Uvicorn на порту `0.0.0.0:8000`.
- Рабочий каталог внутри контейнера — `/app/backend`. Команды Alembic выполняются из него (при локальной разработке — из каталога `backend`).
- Взаимодействие с PostgreSQL реализовано через SQLAlchemy с асинхронным драйвером `asyncpg`. Приложение принимает параметры подключения либо через единую строку `DATABASE_URL`, либо через раздельные переменные `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`. Если заданы оба варианта, приоритет имеет `DATABASE_URL`. Логика обработки описана в [настройках приложения](../backend/app/config.py).
- **Важно:** При старте веб-приложение проверяет соединение с базой данных и инициализирует раунд, но **не применяет миграции автоматически**. Миграции нужно запустить отдельной командой до старта новой версии приложения.

## 🛠️ Развертывание приложения

### Вариант A — Отдельная управляемая БД (например, для облака Amvera)

- Создайте PostgreSQL как отдельный сервис внутри вашего облачного провайдера. Это позволит платформе независимо управлять жизненным циклом БД, дисками и резервными копиями. Создайте базу данных, пользователя и пароль, а затем сохраните эти параметры в менеджере секретов (Secret Manager).

- На платформе Amvera это стандартный сценарий: создается управляемый кластер PostgreSQL, к которому приложение обращается по внутреннему доменному имени с суффиксом `-rw`. Убедитесь, что приложение и БД находятся в одном регионе. Используйте точный адрес из панели управления кластером. Подробнее см. в документации Amvera: [PostgreSQL в Amvera](https://amvera.ru) и [Сетевое взаимодействие](https://amvera.ru).
- В переменные окружения приложения передайте параметры: `DB_HOST`, `DB_PORT` (обычно 5432), `DB_NAME`, `DB_USER` и `DB_PASSWORD`. Публичный TCP-доступ для базы данных открывать не нужно.

Если ваш провайдер предоставляет подключение одной строкой `DATABASE_URL`, убедитесь, что формат URL совместим с SQLAlchemy и драйвером `asyncpg`. Шаблон строки:

```text
postgresql+asyncpg://USER:PASSWORD@HOST:5432/railway
```

*Примечание: спецсимволы в логине и пароле должны быть экранированы (percent-encoded). Если вы сомневаетесь в корректности строки, передайте параметры раздельно — SQLAlchemy соберет URL автоматически.*

### Вариант B — Запуск PostgreSQL в Docker Compose (локально или на VPS)

- Используйте этот вариант для локальной разработки или если ваш хостинг поддерживает оркестрацию контейнеров с постоянными томами (Persistent Volumes). Внутри сети Docker Compose приложение будет обращаться к БД по имени сервиса (`db:5432`).

Пример конфигурации `docker-compose.yml`:

```yaml
services:
  app:
    build:
      context: .
    environment:
      HOST: 0.0.0.0
      PORT: "8000"
      DB_HOST: db
      DB_PORT: "5432"
      DB_NAME: railway
      DB_USER: ${DB_USER}
      DB_PASSWORD: ${DB_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: railway
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U \"$${POSTGRES_USER}\" -d \"$${POSTGRES_DB}\""]
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  postgres_data:
```

> 📌 **Важно:**
> - Настройте внешнюю HTTP-маршрутизацию для сервиса `app` в соответствии с требованиями вашей платформы.
> - **Никогда не публикуйте порт 5432 базы данных наружу.**
> - Использование `volumes` обязательно, иначе при перезапуске контейнера все игровые данные и словари будут удалены.
> - Полный пример рабочей конфигурации находится в файле [docker-compose.yml](../docker-compose.yml) в корне проекта.

### Настройка переменных окружения

Укажите секреты и параметры в защищенной панели вашего облачного провайдера. **Не коммитьте реальные значения ключей и паролей в репозиторий.**

#### Обязательные параметры:

| Переменная | Назначение |
|---|---|
| `JWT_SECRET` | Секретный ключ для подписи JWT-токенов (минимум 32 байта). Сгенерируйте его командой: `python -c "import secrets; print(secrets.token_urlsafe(48))"`. |
| `DATABASE_URL` или компоненты `DB_*` | Параметры подключения к PostgreSQL. |
| `HOST` | Адрес прослушивания для Uvicorn. В контейнере обязательно указывать `0.0.0.0`. |
| `PORT` | Порт приложения. Должен совпадать с портом, который ожидает провайдер (по умолчанию `8000`). |

#### Рекомендуемые параметры:

| Переменная | Значение / Назначение |
|---|---|
| `APP_ENV` | Установите в `production` на сервере. |
| `DEBUG` | `false` для рабочей среды. |
| `APP_NAME` | Отображаемое имя приложения (по умолчанию `Railway`). |
| `JWT_ALGORITHM` | Алгоритм подписи (по умолчанию `HS256`). |

*Полный список актуальных настроек и их дефолтных значений описан в файле `backend/app/config.py` [config.py](../backend/app/config.py).*

Если вы деплоите проект на Amvera, добавьте в корневой файл `amvera.yaml` конфигурацию портов:

```yaml
run:
  containerPort: 8000
  servicePort: 80
```

## 🚀 Первоначальная настройка базы данных и миграции

### Перед запуском миграций:
1. Убедитесь, что база данных создана, а учетная запись имеет права на управление схемой (`CREATE TABLE`, `CREATE INDEX`).
2. Среда, из которой вы запускаете миграции, должна иметь сетевой доступ к БД. Если вы деплоите в облако, запускайте миграции через встроенную консоль платформы (one-off task) или временный контейнер в той же приватной сети.
3. Проверьте, что миграции направлены на целевую базу (например, `railway`), а не на дефолтную системную базу `postgres`.

### Выполнение миграций:

Внутри Docker-контейнера (где рабочий каталог уже `/app/backend`):
```shell
alembic upgrade head
alembic current
```

Для локального запуска через Docker Compose выполните цепочку команд в терминале вашего хоста:
```shell
docker compose up -d db
docker compose run --rm app alembic upgrade head
docker compose up -d app
```

### Что происходит во время миграции:
Alembic последовательно применит файлы из папки [backend/migrations](../backend/migrations):
1. Создаст структуру таблиц.
2. Загрузит базовые данные городов и маршрутов из встроенных JSON-файлов.
3. Импортирует игровой словарь из CSV-файлов в папке `backend/migrations/words`. Таблица `dictionary_words` перед этим должна быть пустой.

## 🔍 Проверка успешности деплоя

1. Убедитесь, что команда `alembic current` возвращает ID последней миграции.
2. Проверьте наполнение таблиц, выполнив SQL-запрос в консоли БД:
   sql SELECT  (SELECT count(*) FROM cities) AS cities, (SELECT count(*) FROM routes) AS routes, (SELECT count(*) FROM dictionary_words) AS dictionary_words;    
Все три счётчика должны быть больше нуля.
3. Откройте в браузере эндпоинт здоровья приложения: https://<ваш-домен>/health. Статус 200 OK с телом {"status":"ok"} подтверждает, что веб-сервер запущен и успешно соединился с PostgreSQL.
4. Перейдите по пути /register/, создайте тестовый аккаунт и проверьте загрузку интерактивной карты.

🛠️ Диагностика проблем

Симптом	Что проверить
Ошибка старта из-за DATABASE_URL / настроек БД	Проверьте корректность учетных данных; убедитесь, что имя хоста указано правильно (для Docker Compose это db, а не localhost).
Ошибка Connection refused или таймаут	База данных ещё не успела подняться. Убедитесь, что для БД настроен корректный healthcheck, а веб-приложение дожидается его готовности.
Эндпоинт /health отдает код 503	Приложение работает, но потеряло связь с PostgreSQL. Проверьте логи сервиса БД и доступы пользователя.
Платформа выдает ошибку 502/503	Проверьте, что Uvicorn слушает интерфейс 0.0.0.0, а не 127.0.0.1, и его порт совпадает с настройками роутера платформы.
После деплоя новой версии сбросился прогресс раунда	Это нормальное поведение MVP: текущее состояние игры хранится в памяти процесса. Любой перезапуск или масштабирование (более 1 реплики) сбросит текущую сессию.
